# 全插件测试整顿设计规格

## 目标

整顿插件现有自动化测试，使测试结果能真实反映可发布风险：保留高价值行为测试，删除重复或依赖源码排版的脆弱断言，为历史核心业务补足纯逻辑覆盖，并在 CI 中对 `master`、`dev` 的推送和拉取请求执行相同检查。

本次不追求让所有 Yunzai 接线代码获得表面上的高覆盖率。应用入口、Bot、Puppeteer、文件系统和真实网络强耦合的代码只保留必要契约；业务判断和输入解析必须提取为无运行时副作用的模块并直接测试。

## 风险分层

### 核心行为

以下行为必须由导入真实生产函数的测试覆盖：

- AI 图片配置迁移、图片下载安全限制、各检测渠道标准化、汇总文案和凭据轮换；
- JMComic 本子 ID、作者黑名单、代理配置同步、命令结果解析；
- EDU 用户状态、宽限期、无效原因、任务结果和状态报告；
- VV 说命令参数解析、API 响应标准化；
- HTTP 静态文件路径解析和 MIME 类型判断；
- 通用代理和外部命令错误脱敏。

新增纯逻辑模块不得依赖 Yunzai 全局变量、插件目录布局、配置监听器、真实网络或外部二进制。现有入口只调用这些模块，不改变用户可见命令和正常输出。

### 结构化契约

默认配置、锅巴多卡片、帮助菜单、包管理和 CI 属于发布契约。测试应解析 JSON/YAML 或调用可独立导出的 schema 构造函数，断言字段、类型和关键限制。只有无法安全导入的薄接线代码，才保留最小源码契约；不得继续用大段 `slice`、调用顺序字符串或正则匹配实现细节代替行为测试。

### 平台与原生组件

普通测试在 Linux 和 Windows 运行。`@contentauth/c2pa-node` 原生冒烟测试继续在两个平台执行，以捕获安装脚本、Node ABI 和平台绑定问题。Linux 额外执行核心模块覆盖率门槛，Windows 不重复生成覆盖率。

## 覆盖率策略

使用 Node.js 22 原生测试覆盖率，不增加 Istanbul、c8 等依赖。新增 `test:coverage` 脚本，通过 `--test-coverage-include` 明确列出核心生产模块，并设置以下最低门槛：

- 行覆盖率：90%；
- 分支覆盖率：80%；
- 函数覆盖率：90%。

门槛只评价列入清单的模块。未列入的应用接线层不能被误报为“已覆盖”，也不能因初始化副作用迫使测试建立庞大的伪 Yunzai 环境。核心模块新增后必须同步加入清单。

## 测试清理

- 删除 `jmBlacklist.test.js` 中重复的“缺少作者字段”场景；
- 将 AI/JM 命令正则定义为共享导出常量，测试真实匹配结果，删除对应源码正则断言；
- 锅巴字段测试改为读取实际 schema，不再截取源码窗口；
- 保留对密钥脱敏、SSRF、重定向、大小限制、代理和跨平台 C2PA 的防回归测试；
- 保留少量无法由行为测试替代的发布契约，删除只验证代码写法、不验证功能结果的断言。

## CI 与提交

`.github/workflows/check_code.yml` 在 `master` 和 `dev` 的 `push`、`pull_request` 上运行。Linux 测试执行 `pnpm test:coverage`，Windows 执行 `pnpm test`，两个平台都先执行 `pnpm test:c2pa`。格式检查和 ESLint 保持只读。

设计文档、测试基础设施、各业务模块和最终清理分别形成带 GPG 签名的原子提交，直接提交到 `dev`，不改写现有未推送提交。
